# RH maker hedge venue: Hyperliquid versus Lighter Core

**Read-only, stopped-archive diagnostic, 2026-09-29 UTC.** The [replay script](../scripts/analyze_hedge_venue_hurdle.py) and [matched rows](../reports/rh-hedge-venue-choice/matched-rows.csv) compare an RH Lighter **perp maker buy** followed by a short hedge on either Hyperliquid (HL) or Lighter Core. They use the *same RH quote time, original base quantity, and future RH exit* for both hedge choices. There was no maker order, fill, hedge, or conversion. This research does not change or read the current RH maker pilot capture.

## Why compare Core

[Lighter Core's official account table](https://apidocs.lighter.xyz/docs/account-types) lists Standard **0 bp maker and 0 bp taker**, with 300 ms taker processing; Premium lists base **0.4 bp maker, 2.8 bp taker**, with 140 ms taker processing. [RH Lighter's separate account table](https://apidocs.rh.lighter.xyz/docs/account-types) lists its own Standard/Premium schedules. [HL's official fee table](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/fees) lists native tier-0 perp taker **4.5 bp** per fill; the archived [per-asset HL metadata](../data/raw/rh-maker-metadata/20260929T210845Z/normalized.json) gives **0.9 bp** for sampled `xyz:NVDA` and `xyz:SILVER` after deployer/growth settings. Thus two HL taker fills charge roughly **9 bp** on native BTC/ETH, versus **1.8 bp** on those xyz markets, while two Core Standard taker fills charge zero explicit fee. Core Premium would charge **5.6 bp** across its two taker fills before differences in notional. These are public-tier scenarios, not authenticated account quotes; changing tier also changes execution timing and cannot be implemented by fee subtraction alone.

The hedge venue also changes spread, depth, future buyback basis, and collateral exposure. RH-domain Lighter and Lighter Core are [separate sequencers, liquidity and settlement domains](https://docs.robinhood.com/chain/lighter-domains/). The RH perp side is USDG-prefunded, while HL/Core collateral is held separately. USDG↔USDC conversion, bridge/transfer costs, margin requirements, funding, and liquidation are omitted here. A Core hedge cannot close an HL position without a further trade.

## Fixed method

The script reads only the stopped [19:39–19:46 BTC/ETH capture](../data/raw/maker-capture/20260929T1939Z/manifest.json) and the stopped [20:22–20:29 NVDA/XAG full-book archive](../reports/maker-book-archive-v1/derived/manifest.json). It reconstructs BTC/ETH full L2 books with the existing nonce-aware decoder and uses the published NVDA/XAG full-book events. The report's [summary](../reports/rh-hedge-venue-choice/summary.json) records input and script SHA-256 hashes. The market-grid/minimum snapshot was collected later that day, so this is a current-constraint counterfactual on earlier prices, not a historical authenticated order record.

- For each asset, anchor at a valid **HL L2 receipt** at least five seconds after the previous anchor. This anchor definition does not depend on which hedge venue looks cheaper. Require RH, HL, and Core books all valid at that anchor, receipt age ≤1 s, source age ≤2 s, and both cross-venue receipt and source skew ≤1 s. Never use a future book for the opening quote.
- Let `q = floor(target_USD / RH best ask, common lot)` at the anchor, for **$100, $250, $500, $1,000**. Check all three venues' published lots, minimum quantities and $10 minimum notionals; do not upsize. Use the *same exact q* in both hedge routes and all four position legs. Walk full book depth to obtain HL/Core hedge sell proceeds and later buyback cost.
- For the close, take the **first** later event-receipt observation in the predeclared **10–16 s** window where all three books again pass those same freshness/skew tests. This is a coverage-based first observation, never a later choice of a more favorable price. Walk the RH bid for the long exit and each hedge ask for the short buyback. A path is omitted if either venue lacks depth; results use **common complete anchors only**, avoiding a biased comparison of different covered times.
- Score synthetic four-leg cash flows: `−RH maker-buy notional + hedge-sell proceeds + RH taker-sell proceeds − hedge-taker-buy cost`. Subtract each venue's explicit fee on **its own actual leg notional**. Show a separate **5 bp reserve on max(RH entry notional, hedge entry notional)**; it is a modeled allowance, not an exchange fee. RH Standard maker and taker explicit fees are zero. The compared difference retains each venue's distinct future buyback basis.

The method uses static displayed quotes at decision and future observation times. It does **not** model the 300 ms Core taker delay, HL order latency, RH queue place, passive fill probability, cancellation race, actual IOC slippage, or completed transaction receipts. The overlapping ten-second paths are correlated. No result is a tradable return or proof that a future hedge can be entered at a displayed bid.

## Common-anchor result

The $1,000 branch is the primary comparison. Values below are **medians across common complete anchors** in dollars per approximately $1,000 RH quote, after four modeled fees and the separate 5 bp reserve. The last column is `Core Standard net − HL net`; positive means Core had the lower full-path cost on that *same* anchor. Individual rows and all smaller sizes are in the [CSV](../reports/rh-hedge-venue-choice/matched-rows.csv).

| Asset | HL L2 anchors | Common complete | HL net | Core Standard net | Core − HL |
| --- | ---: | ---: | ---: | ---: | ---: |
| BTC | 76 | 75 | −$1.425 | −$0.561 | **+$0.868** |
| ETH | 76 | 75 | −$1.471 | −$0.558 | **+$0.927** |
| NVDA | 74 | 52 | −$0.739 | −$0.574 | **+$0.170** |
| XAG | 74 | 68 | −$0.704 | −$0.568 | **+$0.124** |

At $1,000, Core Standard had the lower modeled hurdle on **75/75 BTC, 75/75 ETH, 52/52 NVDA, and 66/68 XAG** common anchors. The difference is about **8.7–9.3 bp** for native crypto and **1.2–1.7 bp** for the lower-fee xyz RWA routes when scaled to RH entry notional. All four median Core paths remained **negative**, and **zero** matched $1,000 paths in either venue reached +$0.10 after the 5 bp reserve. Without that reserve, Core's path was positive in only **9/75 BTC, 10/75 ETH, 3/52 NVDA, and 4/68 XAG** observations. These are static quote-path results conditional on a hypothetical RH maker buy at the displayed bid; actual passive fills are more selective and potentially more adverse.

The size sensitivities show approximately proportional cost differences. Median Core − HL advantages for **$100 / $250 / $500 / $1,000** were BTC **$0.087 / $0.217 / $0.435 / $0.868**, ETH **$0.092 / $0.232 / $0.463 / $0.927**, NVDA **$0.019 / $0.048 / $0.093 / $0.170**, and XAG **$0.013 / $0.032 / $0.063 / $0.124**. No small-size median Core path became positive after reserve. The $100 branch is especially sensitive to fixed operating or conversion costs that were not measured.

Under a **fee-only Core Premium sensitivity on the same books**, the $1,000 median Core net would be roughly **−$1.121 BTC, −$1.118 ETH, −$1.134 NVDA, −$1.128 XAG**. That still looks cheaper than native HL for crypto on these static prices but worse than low-fee HL xyz for NVDA/XAG. It is **not** a Premium execution replay: Premium and Standard processing delays differ, so their actual hedge books and late-fill outcomes could differ.

**Decision:** Core Standard is a credible lower-explicit-fee hedge alternative for a *future separate* RH maker study, especially BTC/ETH, but the stopped-book evidence does not rescue the complete path or justify replacing the current HL benchmark. A causal Core comparison would need to freeze Core processing delay, use first post-fill hedge books after local confirmation, retain RH queue uncertainty, and carry separate Core inventory/funding/collateral through the unwind. This diagnostic ends with the archived matched-book comparison; it launches no experiment.
