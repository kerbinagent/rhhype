# RH/HL passive quote universe screen: frozen method

**Predeclared 2026-09-30 UTC, before any new quote collection.** This is an exploratory public-data screen to choose assets for a later study. It does not edit the four-asset v1 pilot, authenticate, send an order, or infer a passive fill. The [runner](../scripts/passive_universe_screen.py) uses only RH Lighter and Hyperliquid public endpoints.

## Universe and public request budget

Start from unique `other.venue == rh_lighter` / `hl.venue == hyperliquid` perp routes in the current [monitor market plan](../data/paper-monitor/markets.json). Preserve the plan's exact market IDs, including `xyz:` aliases; deduplicate assets and reject conflicting IDs. Before quote collection, make exactly **three** metadata calls: RH `GET /api/v1/orderBookDetails`, HL native `POST /info {"type":"metaAndAssetCtxs","dex":""}`, and HL xyz with `"dex":"xyz"`. Require RH active perp, symbol/market ID match, base multiplier = 1, quote multiplier = 1, consistent supported/current decimals, valid minimums, and published maker fee. Require HL universe name/size decimals, active context, USDC collateral token 0, and derive tier-0 taker fee from the current official [fee schedule](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/fees) plus the metadata's HIP-3 growth/deployer scale. This is a public Standard/tier-0 scenario, not an account-specific fee claim. Require **both** fresh RH `daily_quote_token_volume` and HL `dayNtlVlm` ≥$1 million; missing/nonfinite volume excludes an asset. Rank by the smaller fresh venue volume, descending, tie by asset, and retain at most **22**. Existing BTC/ETH/NVDA/XAG are controls if they pass the same gate; failures are reported, not overridden. Record RH daily trade count where published; do not invent an HL trade count. [RH's API market table](https://apidocs.rh.lighter.xyz/reference/orderbooks), [HL perpetual metadata/context API](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint/perpetuals), and the frozen plan determine this mapping.

Apply a conservative exposure allowlist **before** the volume rank: BTC, ETH, LIT, SOL, HYPE, ZEC, NEAR, XRP; XAU and XAG; and NVDA, AAPL, SNDK, GOOGL, MSFT, MU, TSLA, META, CRCL, AMD, AMZN, INTC. The crypto names require identical symbol and native HL name. XAU/XAG require the plan's `xyz:GOLD`/`xyz:SILVER` alias and one troy ounce reference; the listed US equities require `xyz:` plus the same symbol and one-share reference. [Lighter's published RWA specifications](https://docs.lighter.xyz/trading/real-world-assets-rwas/market-specifications.md) provide the latter units, with the existing [unit provenance](../reports/maker-equity-v2/unit-provenance.json) for NVDA/XAG. Exclude SPCX (private-share mechanics), PONS (token identity), SKHY (cross-currency reference), and SOXL (leveraged-ETF reference) from this screen pending a separate unit audit, even if their plan volume passes. Also require RH index and HL oracle reference prices to agree within 10% at metadata time as a sanity gate; price proximity alone is not proof of exact hedge equivalence. Differences in oracle and settlement remain a limitation even for retained routes.

Quote collection makes **five rounds**, each starting at least 60 seconds after the prior start. It opens one read-only RH WebSocket and subscribes to the selected markets' **ticker BBO and trade channels only**, not full order-book streams. RH ticker has source `last_updated_at` in microseconds, bid/ask price/size, and receipt time; the REST `orderBookOrders` response lacks a book source time, so it is not used. The RH trade channel supplies a descriptive count and notional of post-subscription taker sells (potential contra flow for maker bids) and taker buys (potential contra flow for maker asks), deduplicated by trade ID; it cannot establish our queue fills. Initial trade history snapshots are not counted. Aggregate trade data are reported by asset and round, with an incompleteness flag if the trade ledger cap is reached. For each asset in frozen rank order, issue one **sequential** HL `l2Book` REST request with 20 levels per side, for at most 22 × 5 = **110** book requests. No retry or favorable-quote selection. The three metadata calls and up to 110 HL books are the full REST request budget. No other host receives per-market REST traffic. Concurrency is one for books, below the hard limit of three. Store raw metadata and selected ticker/HL responses, compact post-subscription trade records, and timing under a **16 MB total file cap**; stop without partial records if the cap is reached.

## Matching and score

Use the latest RH ticker already received when each HL request starts; never use a future ticker. Accept a pair only if RH ticker source and receipt and HL book source and receipt are all no more than 2 seconds old at HL receipt, source is no later than its own receipt, and both cross-venue source skew and receipt skew are ≤2 seconds. If RH has no current ticker, HL request fails, either side is crossed/empty, any timestamp check fails, or HL displayed depth is insufficient, mark that asset/round/size missing with a reason. RH top bid/ask sizes are descriptive queue competition, **not proof of a maker fill or a size-feasible passive cycle**. HL asks/bids are walked to exact common base quantity using the market plan's compatible decimal steps and fresh minimums.

For each $100/$250/$500/$1,000 RH quote size, set `q = floor(budget / RH ask / common size step) × common size step`. Reject if q violates RH/HL minimum quantity, RH quote ceiling, or either venue's $10 minimum notional; no upsize to make a candidate pass. The **static unchanged-book** long RH maker cycle buys at RH bid and sells at RH ask. Its short HL hedge sells q into displayed HL bids and buys q from displayed HL asks. Quoted gross = `q×(RH ask−RH bid) + HL bid-walk proceeds − HL ask-walk cost`. Subtract two HL tier-0 taker fees on **their own fill notionals** and any nonzero published RH maker fees on the two RH quote notionals. Record (a) fee-only quoted margin, (b) remaining after the $0.10 target, and (c) remaining after target and a separate 5 bp stress allowance on the larger opening leg. The 5 bp allowance is not a documented exchange fee. The static two-maker scenario is a conditional spread/depth decomposition, **not executable expected return**.

Rank assets for exploratory follow-up by **median** $1,000 margin after fees, $0.10 target, and 5 bp stress across ≥3 valid rounds; tie by fresh minimum 24h venue volume then asset. Report ten best *eligible* assets if ten meet coverage, and separately all missing/depth failures. Do not select by the single most favorable round. Save every round and size, input hashes, quote receipt/source times, market fee/volume/trade-count metadata, and the exact exclusion denominator. Five minute-spaced quotes cannot estimate maker fill probability, adverse selection, funding, conversion, or future return; any positive score only nominates a prospective, independently frozen study.

## Implementation choices frozen before this screen

The runner is standalone and imports only Python standard modules and aiohttp; it freezes its full source, tests, method, market plan, three metadata responses and request provenance, and selected universe with SHA-256 hashes before a separate capture invocation. The capture verifies all hashes, refuses a second attempt in the same output directory, and requires metadata no older than 30 minutes. Five rounds have fixed 60-second minimum start spacing and a fixed three-second subscription warmup. There are no reconnects, retry requests, extra depth calls, or favorable-quote restarts. The RH WebSocket uses documented ping/pong and transport heartbeat only.

HL l2Book returns its documented 20 levels; the request has no invented depth parameter. Every visible level must satisfy the published price and size rule, with strictly ordered unique levels and an uncrossed book. Both RH maker quote notionals and both HL walked notionals must satisfy their fresh/official minimums; both RH notionals must fit the published quote ceiling. The common lot is the larger decimal power-of-ten size step. RH fees are published percentage values converted to basis points. HIP-3 fee scale zero is permitted; missing or unknown growth/scale fails validation. Native HL applies the public 4.5 bp taker scenario. These rules can reduce eligible coverage.

The 16,000,000-byte directory cap includes frozen inputs and all outputs. Raw files stop at 11,000,000 bytes to reserve 5,000,000 bytes for terminal manifest, aggregate flow and ranking. The trade ledger stores at most 20,000 unique valid ordinary prints; later prints mark it incomplete. Count only update/trade source times at or after that market's subscription acknowledgement receipt; exclude subscription history, liquidations, malformed records, future prints, older updates and duplicates. Warmup flow is round -1. Subsequent round flow buckets begin at round start and include the waiting interval until the next round starts; the final bucket stops after its quotes. This descriptive flow has no attribution to hypothetical orders or quote prices. Quote result rows preserve raw HL response text, its hash, the selected raw RH ticker, four size outcomes and all timing.

Offline tests cover future/stale/missing/crossed/off-grid/depth failures, common-lot rounding without upsizing, each fill's own fee notional, separate target and stress, minimum round coverage and median ranking, metadata exclusions, trade snapshot/old/duplicate handling, and no partial cap record. No production or frozen passive-exit pilot files are changed.
